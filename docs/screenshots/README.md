# 截图说明

本目录用于存放 README 与发布说明中的界面截图。当前仓库**不包含**任何图片文件，README 中也不引用图片，以避免坏链；需要时请按下述清单自行截图并补充。

## 建议截取的画面

| 序号 | 画面 | 建议内容 | 用途 |
| --- | --- | --- | --- |
| 1 | 资产台账列表 | 至少 8 条资产，覆盖在用 / 闲置 / 维修 / 报废四种状态，勾选 2-3 行，显示搜索与筛选控件 | 最能说明产品定位，通常放在最前 |
| 2 | 标签打印预览 | 选择「A4 不干胶 · 3 列」，右侧显示完整纸张预览与模板参数 | 展示核心差异化能力 |
| 3 | 扫码盘点进行中 | 带摄像头取景框、进度条、已盘/未盘清单 | 展示移动端使用场景 |
| 4 | 资产表单（含照片） | 打开「编辑资产」弹窗，已上传压缩后的照片与「已压缩 38KB（640×480）」提示 | 展示照片压缩链路 |
| 5 | 盘点结果 / 记录 | 历史批次列表或盘亏明细 | 可选，用于说明盘点闭环 |

加分项：一张手机竖屏的扫码截图（真实设备、真实光线），比桌面端的模拟效果更有说服力。

## 尺寸与格式

- 桌面端：1600×1000 像素，PNG，优先截浏览器内容区，不要带系统窗口边框与个人书签栏。
- 移动端：1170×2532 或同等比例，PNG。
- 单张控制在 500KB 以内；超过时可用 `pngquant` 或 TinyPNG 压缩，但不要牺牲文字可读性。
- 文件名用小写英文与连字符：`assets-list.png`、`label-preview.png`、`scan-stocktake.png`、`asset-form-photo.png`、`stocktake-result.png`。

## 截图步骤

1. 生成单文件版本，避免本地服务带来的地址栏干扰：

   ```bash
   node build-standalone.mjs
   ```

2. 打开 `资产管理.html`，用 `admin` / `admin123` 登录。
3. 在「资产台账」点「载入示例数据」，或导入 `examples/sample-backup.json`（示例备份含 12 条资产与 1 条盘点记录）。
4. 需要照片的画面：随便上传一张本地图片，页面会自动压缩并显示压缩后体积；本地 `file://` 下上传会失败并提示「暂存本机」，截图时请改用 `python3 -m http.server 8000` 通过 `localhost` 打开，或直接用示例备份里自带的占位图。
5. 浏览器缩放到 100%，窗口宽度建议 1600px 左右，避免出现横向滚动条。
6. 若要展示深色模式，请在系统设置中切换后重新截图，不要用后期滤镜。

## 注意事项

- 截图前请清空真实数据，或使用示例数据。**不要**让真实资产编号、姓名、内网地址、服务器域名、书签栏出现在画面中。
- 涉及个人姓名的画面，建议用「张伟」「李娜」这类示例姓名，与 `examples/sample-backup.json` 保持一致。
- 提交截图时请同时更新本文件的表格或在 PR 描述中说明用途；不要把图片放进 `assets/` 之外的位置，也不要让 README 依赖外链图床。
- 图片属于二进制文件，已在 `.gitattributes` 中标记，避免行尾转换损坏文件。
